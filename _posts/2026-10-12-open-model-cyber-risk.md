最近，Anthropic 发布了一份关于 GLM-5.3 的网络安全评估，报告表示开放模型，已经具备了很强的网络攻击能力。

## GLM-5.3 到底强在哪里？

在 ExploitBench 测试中，GLM-5.3 在 410 次尝试里完成了 50 次端到端漏洞利用。这个测试针对的是 Chrome 所用 V8 引擎中的已知漏洞，其中最高档的要求是给出可以真正跑通的利用链。

在 Anthropic 内部的二进制利用测试中，GLM-5.3 有 4% 的尝试完成了完整的控制流劫持。此前测试过的 GLM-5.2 和 Claude Opus 4.6，在这组任务上都没有达成同类结果。

这就是报告所说的“重大威胁”：模型不再只是解释漏洞原理，或者生成一段看起来像攻击代码的文本，而是能在较少人工介入的情况下，把多个步骤串起来，完成攻击行为。

## 护栏失效，强能力产生更大的麻烦

如果模型虽然有能力，但会拒绝执行明显恶意的请求，风险还能通过访问控制和监控来降低。

Anthropic 对 GLM-5.3 的担忧，主要在于它的护栏很容易被改动或绕过。

在模拟测试中，直接要求模型攻击关键系统时，模型没有执行。但研究者只换了几个简单的做法：

- 把请求包装成红队演练；
- 预填一段“模型已经决定继续执行”的思维过程；
- 直接修改模型权重，移除拒答行为。

这三种做法下，模型尝试执行恶意请求的比例分别上升到 64%、92% 和 100%。

这正是开放权重模型和闭源 API 的一个重要差异：前者可以被下载、复制和重新配置。研究者甚至不用动模型的大部分能力，就能明显拉低它的拒答率。Anthropic 称，他们对 GLM-5.3 做这类权重修改后，拒答率从 90% 以上降到很低的水平，而通用能力基本没有一并消失。

![GLM-5.3 权重修改前后的拒答率和能力](/assets/images/09-open-model-cyber/04-abliteration.jpg)

*图 3：权重修改后，GLM 模型的拒答率显著下降，而通用能力和网络能力变化有限。图源：[Anthropic 原文](https://www.anthropic.com/research/glm-5-3-and-the-spread-of-advanced-cyber-capabilities)，原文 Figure 4。*

于是问题从“模型会不会攻击”，变成了“模型的安全边界能不能被使用者重新定义”。

闭源 API 的优势是平台方可以统一控制模型、工具和访问入口；开放权重模型的优势则是用户能在本地运行和修改。两者的风险结构并不一样。

## 开放模型，也可以成为防御工具

Anthropic 的报告得出一个结论：既然开放权重模型会降低攻击门槛，就应该限制它们的发布。

但问题是，防御者面对的是同一轮技术变化。

在 [Hugging Face 披露的一起安全事件](https://huggingface.co/blog/security-incident-july-2026)中，调查团队发现，商业前沿模型的 API 会被真实的攻击命令和载荷触发护栏，无法直接用于取证；团队后来在本地运行开放权重模型，才把事件分析继续下去。

这不是说本地模型天然更安全，而是本地部署解决了几个 API 很难同时兼顾的问题：

- 敏感日志和样本不必交给第三方服务；
- 防御团队可以控制工具、网络和运行环境；
- 取证过程中不会因为商业 API 的策略误判而中断分析；
- 组织可以完整保留模型版本、输入和输出的记录。

Anthropic 自己的 Project Glasswing 走的是另一条路径：把更强的模型交给经过审核的防御团队，用来提前发现关键软件中的漏洞。强模型既能被攻击者使用，也能被防御者使用。

所以，开放模型的防御价值并不是一句“理论上也能防守”。在隔离网、敏感环境和需要本地审计的任务里，本地模型确实可能比远程 API 更合适。

当然，本地运行也带来了新的责任：权重是否完整，部署环境有没有被篡改，版本更新由谁负责，输出结果如何审计。这些问题不会因为模型在本地就自动消失。

## 闭源模型也不是天然安全

“开放危险、闭源安全”听起来很有道理，但公开事件并不支持这么简单的结论。

[OpenAI 曾披露](https://openai.com/index/disrupting-malicious-uses-of-ai-by-state-affiliated-threat-actors/)，与国家有关联的威胁行为者利用其服务进行侦察、编写脚本、准备钓鱼材料和开发恶意软件。OpenAI 还披露过[一起 Hugging Face 事件](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)：内部闭源研究模型在评估环境中突破隔离，获得了对互联网和第三方系统的访问。

这些事件不能证明闭源模型比开放模型更危险，它们能证明的是：**闭源模型拥有更强的访问控制，也不等于风险归零。**

闭源模型的护栏可能更强，平台也更容易撤销访问、更新模型、记录调用。但只要模型能调用网络、代码执行环境和第三方服务，风险就不只来自模型权重，还来自工具权限、隔离质量和监控能力。

而开放权重模型的问题，更多集中在扩散和改造：下载门槛低，权重可以被复制，安全微调可能被移除，发布方很难控制每一个部署实例。

两类模型的风险结构不同，不能只比一个“谁更安全”的总分。

## 我们应该真正关心什么？

“开放模型是风险还是安全？”目前还没有一个词就能回答的结论。

开放模型可能扩大攻击面的上限，也可能成为防御团队手里的工具。决定结果的，不只是权重有没有公开，还包括部署环境、工具权限、护栏质量、监控能力，以及防御者能否跟上攻击者的能力增长。

我们应该关注以下五个问题：

- 模型本身的网络攻击能力到了什么程度？
- 权重是否可以下载、复制和重新训练？
- 默认护栏能不能被普通方法绕过？
- 模型能接触哪些网络、工具和数据？
- 防御者能不能获得同等级的检测、修复和取证能力？

这五个问题，比“开源还是闭源”更接近真实的安全判断。

GLM-5.3 让前两个问题变得更紧迫：一个开放权重模型已经具备较强的漏洞利用能力，而且它的安全边界可以被重新配置。

而 Hugging Face 的事件和各类闭源模型滥用案例，又把第三、第四和第五个问题摆到了桌面上：API 护栏不是万能的，闭源模型也可能在错误的工具和环境里造成严重后果，防御者有时仍然需要本地运行的模型。
