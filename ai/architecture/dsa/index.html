从第一性原理理解DSA

假设你把一个很长的代码仓库交给模型，问它「数据库写入失败后，去哪里改重试次数？」答案可能藏在很早出现的配置文件里。处理到问题末尾时，模型怎样跳过大量无关内容，找到那几处真正有用的位置？

DSA（DeepSeek Sparse Attention，DeepSeek 稀疏注意力机制）就是为长上下文里的这个问题设计的。它先快速筛选候选位置，再对选中的 Token 执行完整的注意力计算。

它与之前讨论的 MHA、GQA、MLA 分别优化注意力的不同部分。

  • MHA：每个注意力头独立计算 QKV。
  • GQA：多个 Query Head 共享 KV Head。
  • MLA：通过低秩压缩减少 KV Cache。
  • DSA：让每个 Query 只选择最相关的一部分历史 Token 进行完整的注意力计算。

GQA 和 MLA 主要优化信息的存储与访问，而 DSA 主要优化参与 Attention 的 Token 数量。

1. DSA 要解决什么问题？

假设模型拥有 100 万 Token 的上下文。

传统 Full Attention 在生成下一个 Token 时，当前 Query 需要与全部历史 Key 进行匹配。

但是，当前 Token 真的需要关注全部 100 万个 Token 吗？

DSA 的核心思想是：先通过一个低成本的索引机制筛选出最相关的历史 Token，再执行高精度的 Attention 计算。

2. DSA 的完整计算流程

DSA 最早在 DeepSeek-V3.2-Exp 中引入，在 DeepSeek-V3.2 中正式使用，主要包含两个核心组件：

  • Lightning Indexer（闪电索引器）。
  • Fine-grained Token Selection（细粒度 Token 选择机制）。

3. Lightning Indexer 是如何计算的？

这里非常值得研究，因为它实际上又构建了一套轻量级的 QK 计算机制。

之前我们讨论过传统 Attention：

Q=XWQ,K=XWK,V=XWVQ=XW_Q,\quad K=XW_K,\quad V=XW_V

DSA 则额外引入索引器使用的 Q、K 和权重：

QI=XWQIQ^I=XW_Q^I

KI=XWKIK^I=XW_K^I

wI=XWwIw^I=XW_w^I

这里是简化表示，实际 DeepSeek 实现中的 Indexer Query 使用 MLA 的低秩 Query 表示进行投影。

DeepSeek-V3.2 的 Indexer 配置为：

参数 数值
Index Query Heads 64
Index Key Heads 1
Index Head Dimension 128
Index Top-K 2048

Hugging Face

Indexer 的核心公式：

It,s=∑j=1HIwt,jI⋅ReLU(qt,jI⋅ksI)I_{t,s}=\sum_{j=1}^{H^I}w^I_{t,j}\cdot\operatorname{ReLU}\!\left(q^I_{t,j}\cdot k^I_s\right)

其中：

符号 含义
t 当前 Query Token 的位置
s 历史 Token 的位置
j Indexer Head 编号
qt,jIq^I_{t,j} 当前 Token 的索引 Query
ksIk^I_s 历史 Token 的索引 Key
wt,jIw^I_{t,j} 当前 Token 对该索引头的权重
It,sI_{t,s} 最终索引分数

注意，这里使用的是 ReLU，而不是 Softmax，而且没有计算 V。

它的目的不是聚合信息，而是判断哪些 Token 值得进入下一阶段的 Attention。

6. DSA 到底节省了多少计算量？

假设 Top-K 固定为 2048，仅比较正式 Attention 阶段每个 Query 需要处理的历史 Token 数量。

但是这里有一个非常重要的问题。

Indexer 自己不还是需要遍历全部 Token 吗？

是的。

因此，如果严格分析复杂度：

计算阶段 Full Attention DSA
Prefill 主 Attention O(T²) O(TK)
Prefill Indexer 无 O(T²)
Decode 主 Attention O(T) O(K)
Decode Indexer 无 O(T)

以上省略了特征维度、Head 数量和 Top-K 选择本身的计算成本。

DSA 并没有彻底消除平方复杂度，而是将昂贵的全量 Attention 替换为低成本的全量索引计算，加上高成本的稀疏 Attention。

随着上下文继续扩大，Indexer 本身也可能成为性能瓶颈。

7. Indexer 是怎么训练出来的？

这可能是 DSA 最有意思的地方。

如果 Indexer 选错了 Token，就可能丢失关键信息。因此 DeepSeek 采用了两个阶段进行继续预训练。

DeepSeek-V3.2 论文公开的训练规模：

阶段 训练步数 训练 Token 数量
Dense Warm-up 1,000 2.1B
Sparse Training 15,000 943.7B

DeepSeek-V3.2 技术报告

因此 DSA 并不是简单地给原模型增加一个 Top-K 函数，而是需要让模型通过训练适应这种新的信息选择机制。

10. 从第一性原理理解 DSA

传统 Transformer 的假设是：

每个 Token 都应该计算自己与所有历史 Token 之间的注意力关系。

DSA 则改变了这个假设：

信息的重要性是不均匀的，可以先进行低成本筛选，再对少量重要信息进行高成本计算。

从架构思想来看，DSA 有些类似于将检索机制引入 Transformer 的内部。

它与 MoE 甚至存在一定的思想共性：

架构 动态选择的对象
MoE 哪些专家参与计算
DSA 哪些历史 Token 参与注意力计算
RAG 哪些外部文档进入模型上下文

三者都在探索同一个问题：如何在拥有大量可用信息或计算资源的情况下，只激活当前任务真正需要的部分。

DSA 的核心价值是将计算资源从全量分配转变为按信息相关性动态分配。 这也是长上下文模型能够进一步扩展的重要技术方向。
